# Процедурный прототип виртуального тура — КТ2

Прототип выполнен на Python 3.14.x в процедурном стиле: сущности представлены словарями и списками словарей, пользовательские классы не объявляются. Используется только стандартная библиотека Python.

## Запуск

В командной строке перейдите в эту папку `src` и запустите:

```text
py -3.14 main.py
```

Либо укажите собственные входной и выходной файлы JSON:

```text
py -3.14 main.py --input example_input.json --output result.json
```

`example_input.json` содержит демонстрационный набор: комнаты, панорамы объекта, идентификатор объекта и оператора. Прототип сформирует предложения сопоставления, создаст черновик тура и сцены, проверит структуру и сохранит опубликованную версию в `result.json`.


Для Linux/macOS из каталога `src` (требуется установленный Python 3):

```text
python3 main.py
```

Ожидаемый вывод для `example_input.json`:

```text
Предложений помещений: 3
Создано сцен: 3; проверка: успешно
Опубликована версия 1: https://example.invalid/tours/1/v/1
Файл результата: result.json
```

## Процедурные операции

| Операция BPMN | Функция | Назначение |
|---|---|---|
| Создать черновик тура | `create_tour_draft()` | Добавляет запись тура со статусом `draft`. |
| Загрузить панорамы и создать сцены | `load_panorama_scenes()` | Проверяет, что панорамы относятся к нужному объекту, и создаёт сцены. |
| Предложить сопоставление панорам помещениям | `suggest_room_matches()` | Сравнивает нормализованные имена. Точное совпадение получает балл 3, совпадение по синониму — 2; равные лучшие варианты и отсутствие совпадений направляются на ручную проверку. |
| Проверить структуру и достижимость тура | `check_tour_graph()` | Проверяет старт, ссылки на панорамы, концы переходов и достижимость сцен обходом в ширину. |
| Опубликовать проверенную версию и сформировать URL | `publish_tour_version()` | Запрещает публикацию при ошибках и добавляет новую запись версии. |

## Алгоритмы и сложность

В `tour_algorithms.py` реализованы два алгоритма из отчёта. Для проверки графа `V` — число сцен, `P` — число панорам, `E` — число переходов. Полное время — `O(V × P + V + E)`: для каждой сцены `any()` может просмотреть все панорамы. При `P = V` это `O(V² + E)`. Сам BFS занимает `O(V + E)`, дополнительная память всей функции — `O(V + E)`.

Для сопоставления `P` — число панорам, `R` — число помещений, `S` — максимальное число синонимов помещения, `L` — максимальная длина строки. Нормализация имени и синонимов повторяется для каждой пары, поэтому время — `O(P × R × (S + 1) × L)`. Эта оценка предполагает обычную модель хеш-таблиц со средним `O(1)` для операций; при патологических коллизиях консервативная граница — `O(P × R × (S + 1)² × L)`. Память с результатами — `O(P × R + R + S × L)`, поскольку неоднозначные предложения могут сохранять все R кандидатов для каждой панорамы.

`tour_workflow.py` содержит операции подготовки и публикации. Публикация запускает проверку графа повторно и создаёт версию только при успешном результате. `main.py` связывает операции и читает/записывает JSON.

## Ограничения учебного прототипа

Загрузка здесь означает регистрацию метаданных уже подготовленных файлов; сами панорамные изображения не перекодируются и не размещаются на сервере. `example.invalid` — зарезервированный демонстрационный домен, поэтому сформированный URL является заглушкой, а публикация в интернете не выполняется. В реальной системе URL создавался бы после загрузки файлов и сохранения версии на сервере. Переходы задаются оператором; в демонстрационном JSON они соединяют три сцены в достижимый маршрут.
